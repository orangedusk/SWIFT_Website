## Naming Conventions

**Files:**

- **HTML:** `index.html` (single entry point)
- **JS scripts:** `.mjs` (ES modules) for dev tools, inline `<script>` for app code
- **Images:** kebab-case + descriptive (e.g., `hero-doctor-patient.jpg`, `clinic-waiting-area.jpg`)
- **JSON:** `package.json` (standard)

**HTML IDs:**

- Prefixed by section or component: `heroImg`, `visitStepper`, `campaignModal`, `viewportSwitcher`
- Kebab-case for data attributes: `data-step="0"`, `data-viewport="mobile"`, `data-bar="top"`
- Consistent action suffixes: `Btn` (button), `Modal` (modal container), `Menu` (menu container)

**CSS Classes:**

- Tailwind utility classes: standard breakpoint prefixes (`sm:`, `md:`, `lg:`)
- Custom classes: camelCase for component state (`is-open`, `is-visible`, `is-swapping`, `is-current`)
- Data-driven styling: `.triage-row[open]` (native HTML state), `.faq-item[open]` (native HTML state)

**JavaScript Variables:**

- camelCase: `currentStep`, `heroImg`, `statusEl`, `triggers`, `campaigns`, `nodes`
- Constant-like in closures: `steps`, `NODE_ACTIVE`, `NODE_PAST`, `NODE_FUTURE`, `MIME_TYPES`
- Private to IIFE: all variables scoped to function; no globals (intentional isolation)

**Media Assets:**

- Descriptive names: `clinic-reception.jpg` (not `clinic-1.jpg`)
- Visit journey steps: `Arrive.jpeg`, `Register.jpeg`, etc. (PascalCase, matching JS step titles)
- Campaign variants: descriptive (`Flu_shot.jpeg`, `school_holidays.jpeg`)

## Where to Add New Code

**New Component/Section:**

- Add HTML markup in `index.html` immediately before `</main>` (before footer, line ~804)
- Create new `<section id="newSection">` with appropriate scroll-margin-top
- Use existing section structure: heading (h2, `.reveal` class), content grid/flex
- Example: copy structure from services section (lines 482–485)

**New Feature/Interactivity:**

- Add new IIFE module in `<script>` tag (line 849–1153)
- Create IDs/data attributes in markup for DOM element references
- Isolate state inside IIFE closure
- Follow existing pattern: query elements → check if exist (`if (!el) return;`) → attach event listeners → define state update functions
- Example: copy structure from mobile menu IIFE (lines 888–918) or campaign modal (lines 1007–1098)

**New Hero Campaign Variant:**

- Add image file to `brand_assets/` (e.g., `campaign-name.jpeg`)
- Add campaign object to `campaigns` array (line 1008–1045)
- Populate: `id`, `label`, `desc`, `swatch` (hex color for preview), `image`, `imageAlt`, `headline`, `subhead`, `ctaText`, `ctaHref`
- JavaScript automatically renders campaign button in modal; no code changes needed

**New Service Offering:**

- Add `<a>` card to services grid (lines 487–558)
- Copy existing card structure: icon div + h3 + p
- Update icon SVG, text, href
- If featured large tile needed: add `col-span-2 md:row-span-2` classes + larger image

**New Section Images:**

- Add to `brand_assets/` (PNG for logos/icons, JPG for photos)
- Reference in HTML: `src="brand_assets/filename.ext"`
- No image optimization step; serve as-is (consider manual compression before commit)

**Utilities/Helper Functions:**

- No separate utilities file (single-file architecture)
- Add helper functions inside IIFE modules as needed, or create new IIFE if reusable across modules
- Example: timezone check (lines 856–859) could be extracted to helper, but currently inline

**Testing:**

- No automated test suite currently
- Manual testing: `node serve.mjs` → open `http://localhost:3000` → browser DevTools
- Visual regression: `node screenshot.mjs http://localhost:3000 [label]` → compare outputs
- Mobile testing: `node mobile_shot.mjs http://localhost:3000 [label]`
